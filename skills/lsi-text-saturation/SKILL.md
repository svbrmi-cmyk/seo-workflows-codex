# Насыщение текста LSI

Редактировать весь текст. Сохранять факты, смысл, структуру, коммерческую задачу, техническую точность, предметную полноту и естественный русский язык. Не считать формально сошедшиеся счетчики достаточным результатом, если текст стал беднее, менее точным или менее полезным.

## Приоритеты решений

Применять правила в таком порядке:

1. прямое условие пользователя;
2. фактическая и техническая точность;
3. обязательные сущности темы и интента страницы;
4. релевантная ширина полной LSI-таблицы;
5. медианное ядро без превышения;
6. отрицательные рекомендации для неосновных слов;
7. стилистическая вариативность.

Нижестоящее правило не может отменять вышестоящее. Нельзя удалить ключевую сущность только ради `0` в максимуме, заменить ее расплывчатым словом и объявить задачу выполненной.

## Сначала определить набор входов

Прочитать [references/excel-format.md](references/excel-format.md). Использовать только файлы одной итерации анализатора: одинаковый идентификатор в именах файлов и один анализируемый текст.

Поддерживать два режима. Если пользователь передал все три таблицы, применять их совместно: LSI задает ширину, медиана — целевое ядро, полная глубина — добавления и сокращения.

### Полный LSI

Если есть большая LSI-таблица со сводным листом и медианой, взять первые 150 разных групп. Это основной пул ширины.

### Медиана + полная глубина

Если переданы:

- короткая таблица gar_deep__median... с колонкой Медиана;
- полная таблица `gar_deep...` с минимумом, максимумом и `Добавить/Удалить`;

объединить их по группе словоформ. Короткая таблица задает только ядро и не измеряет ширину. Полная таблица добавляет:

- положительные группы для ширины и глубины;
- отрицательные группы для сокращения переспама.

Запустить:

```powershell
python scripts/build_saturation_plan.py --source исходник.txt --text текущий.txt --median gar_deep__median.xlsx --deep gar_deep.xlsx --exclude исключить.txt --json-output план.json
```

Не применять белый список прошлой итерации как знаменатель нового охвата.

## Иерархия целей и лимитов

Для каждой релевантной группы определи цель и верхний предел.

1. Если группа присутствует в таблице текущей медианы:
   - цель = медиана;
   - верхний предел = медиана.
2. Если медиана отсутствует, но полная таблица дает положительный минимум:
   - цель = минимум;
   - верхний предел = максимум;
   - для группы с нулем в исходнике сначала обеспечить одно употребление.
3. Если в текущей таблице медиана явно равна нулю:
   - не добавлять группу.
4. Если `Добавить/Удалить` отрицательно:
   - считать строку обязательным ограничением;
   - сократить группу до максимума, а при максимуме `0` — до нуля.
5. Если источники одной итерации расходятся, сначала определить роль группы:
   - для служебного, второстепенного или заменимого слова использовать более жесткий верхний предел;
   - для обязательной предметной сущности сохранить минимально достаточное естественное употребление, пометить `SEMANTIC_CONFLICT` и не выдавать нарушение лимита за ошибку редактора;
   - если медиана требует добавить нерелевантный бренд, интерфейсное слово или чужую категорию, исключить группу с причиной, даже при высокой медиане.

### Режим «подогнать под медиану»

Если пользователь прямо просит ориентироваться на медиану и не превышать ее:

- довести до медианы только релевантные группы;
- не добавлять неподтвержденный бренд, географию, свойство или ассортимент;
- распределить группу между разными абзацами и смысловыми функциями;
- не удалять обязательные сущности темы по отрицательной строке полной глубины;
- сокращать до указанного максимума неосновные слова;
- считать точное совпадение с медианой целью, но не ценой деградации текста.

Всегда пересчитывать исходный и итоговый тексты самостоятельно. Значение `Повторы` использовать для обнаружения расхождения, а не как окончательный счетчик.

Считать группу только суммой всех перечисленных словоформ. Никогда не считать одно представительное слово вместо группы. Например:

`мебель = мебель + мебели + мебелью`.

После объединения форм сверить собственный счетчик с колонкой `Повторы`. Расхождение считать ошибкой разбора до выяснения причины.

## Настоящий охват

Не считать охватом точную подгонку небольшого ядра.

Сформировать знаменатель как объединение:

- релевантных групп первых 150 строк полной LSI-таблицы;
- всех релевантных положительных строк полной таблицы глубины текущей итерации.

Не удалять группу из знаменателя потому, что она отсутствует в тексте или ее трудно вставить.

Исключать только после смысловой проверки:

- юридику, авторизацию, футер и интерфейс;
- чужие бренды и категории;
- неподтвержденные свойства и факты;
- слова, не относящиеся к назначению страницы.

Для каждого исключения записывать причину. Высокая медиана не доказывает релевантность. Пример: `корзина` может иметь высокую медиану из-за интерфейса магазина.

Считать только как внутренние показатели локального аудита:

`внутреннее покрытие групп = число покрытых релевантных групп / полный релевантный знаменатель`.

`выполнение локальных целей = сумма min(факт, цель) / сумма целей релевантных положительных групп`.

Не называть эти значения охватом, шириной облака, ТОП слов, глубиной облака, релевантностью сайта или общей релевантностью исходного анализатора.

Если пользователь дал метрики анализатора, хранить их как `USER_PROVIDED` и воспроизводить только его формулу. Итоговые метрики после редактирования считать неизвестными до повторного прогона в том же сервисе. Не выводить их из локальных JSON, числа покрытых групп или медиан.

## Алгоритм редактирования

### 1. Построить карту

- Объединить словоформы.
- Пересчитать вхождения по границам слов без учета регистра.
- Разметить каждую группу: `обязательная сущность`, `ядро медианы`, `поддерживающая положительная`, `неосновная отрицательная`, `шум`, `конфликт`.
- Отдельно выписать положительные группы с текущим значением `0`. Это обязательный список ширины.
- Ранжировать ядро по медиане.
- До редакторских замен составить список защищенных сущностей: основной товар или услуга, виды, компоненты, материалы, ключевые характеристики, процессы выбора и эксплуатации, связанные товарные направления страницы.
- Проверить каждую отрицательную строку с максимумом `0` против защищенного списка.

### 2. Проверить новые факты

Если отсутствующая группа обозначает категорию, коллекцию, материал, страну или характеристику, проверить ее по странице магазина, официальному источнику или переданным данным. Не вставлять неподтвержденное утверждение только ради счетчика.

### 3. Сначала расширить словарь

- Пройти все релевантные положительные группы с нулевым текущим значением.
- Добавить каждую хотя бы один раз до повторного усиления низкоприоритетных слов.
- Распределить новые группы между разными смысловыми разделами.
- Не собирать перечень ключей в одном искусственном абзаце.
- Не считать семантическим расширением замену точного термина общим словом вроде `изделие`, `емкость`, `оборудование` или `рабочая зона`, если из текста исчезает необходимое понятие.

### 4. Усилить ядро и средние группы

- Приближать медианное ядро к медиане заметно агрессивнее остальных слов.
- Затем довести положительные группы до минимума, если это остается естественным.
- Перед каждым добавлением проверять верхний предел.
- Не превышать медиану для групп с медианой и максимум для групп без нее.

### 5. Выполнить отрицательные рекомендации

- Сократить все неосновные строки с отрицательным `Добавить/Удалить`.
- Для обязательной сущности с конфликтующим максимумом сохранить минимально достаточное количество, отметить конфликт и объяснить решение.
- Не заменять каждое удаление одним синонимом.
- Использовать удаление, местоимение, перестройку фразы, родовое обозначение и разные контекстные эквиваленты.
- Повторно пересчитать новые слова-замены, чтобы они не стали следующим переспамом.
- После сокращения повторно проверить семантическую карту: удаление переспама не должно убрать типы, материалы, детали, критерии выбора, риски и связанные сущности, необходимые читателю.

### 6. Устранить монокультуру

Применять проверку ко всей обвязке добавлений и замен:

- существительным;
- глаголам;
- прилагательным;
- наречиям;
- модальным конструкциям;
- одинаковым началам и окончаниям предложений;
- новым биграммам и триграммам.

Если целевое слово нужно несколько раз, менять синтаксис и смысловую функцию предложения. Не повторять одну формулу наподобие `уточняйте актуальное наличие заранее`.

### 7. Проверить

Для режима полного LSI использовать `validate_lsi_saturation.py`.

Для режима медиана + полная глубина использовать:

```powershell
python scripts/build_saturation_plan.py --source исходник.txt --text результат.txt --median gar_deep__median.xlsx --deep gar_deep.xlsx --exclude исключить.txt --json-output аудит.json --strict
```

Исправить:

- непокрытые релевантные положительные группы;
- недобор ядра и положительных целей;
- превышения медианы или максимума;
- невыполненные отрицательные строки;
- скопления по абзацам;
- повторяющуюся обвязку;
- символ U+0451;
- неестественные или недостоверные формулировки.

Перечитать текст без таблиц как редактор и выполнить два смысловых теста:

1. **Тест предметной полноты:** сохранились ли основной объект, его виды, состав, материалы, характеристики, выбор, эксплуатация и ограничения.
2. **Тест обратной замены:** не появились ли вместо точных терминов повторяющиеся общие слова только для прохождения счетчиков.

Если числовой валидатор проходит, а любой смысловой тест провален, результат считать `SEMANTIC_REGRESSION`, вернуть точные термины и повторить редактуру.

Если `--strict` не проходит только из-за монокультуры, не скрывать это. Исправлять повторяющуюся обвязку, пока изменения остаются естественными. Если полное устранение конфликтует с явной медианой пользователя, сохранить более качественный текст и указать остаточное предупреждение; не называть строгую проверку пройденной.

## Неподвижные ограничения

- Не смешивать разные итерации анализатора.
- Не использовать старый белый список для доказательства высокого охвата.
- Не придумывать ассортимент, свойства, совместимость, материалы, гарантии, цены, наличие или доставку.
- Не менять факты, названия, артикулы, числа и технические детали.
- Не удалять основную товарную и техническую лексику до нуля только из-за отрицательной строки анализатора.
- Не ослаблять семантику общими заменами ради формального `PASS`.
- Не выдавать локальное покрытие групп и выполнение целей за показатели внешнего анализатора.
- Использовать букву `е` вместо символа U+0451.
- Не заканчивать только диагностикой, если пользователь передал текст для редактирования.

## Результат

Вернуть и сохранить:

1. полный отредактированный текст;
2. аудит ширины и глубины до/после;
3. счетчики ядра;
4. выполненные отрицательные рекомендации;
5. исключенный шум с причинами;
6. непокрытые релевантные группы с причинами;
7. предупреждения о фактах и монокультуре.

В аудите отдельно указывать:

- `Метрики анализатора пользователя` — только фактически переданные или полученные повторным прогоном;
- `Внутренние счетчики` — покрытые группы, выполнение локальных целей, превышения и отрицательные строки;
- `Конфликты таблиц` — обязательные сущности, которые сохранены вопреки ошибочному или семантически разрушительному лимиту;
- `Семантический контроль` — какие основные сущности были защищены и сохранились.
