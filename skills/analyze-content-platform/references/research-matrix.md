# Матрица исследования площадки

## Содержание

1. Карточка публикации
2. Анализ аудитории
3. Анализ комментариев
4. Проверка алгоритма
5. Тематическая матрица
6. Формат итогового отчёта
7. Редакционный чек-лист

## 1. Карточка публикации

Фиксировать по каждому материалу:

| Поле | Что записывать |
|---|---|
| Ссылка и дата | URL, дата и время выхода |
| Автор | Имя, тип аккаунта, примерный размер аудитории |
| Тема | Основной вопрос материала |
| Формат | Кейс, инструкция, разбор, исследование, мнение и другое |
| Заголовок | Полная формулировка и основной триггер |
| Первый абзац | Ситуация, обещание, цифра, конфликт, вопрос или вводная |
| Структура | Подзаголовки, списки, логика раскрытия |
| Фактура | Цифры, кейсы, примеры, цитаты, источники |
| Позиция автора | Есть ли самостоятельный вывод |
| Объём | Доступная оценка длины или времени чтения |
| Визуал | Тип обложки и внутренних материалов |
| Результат | Просмотры, реакции, комментарии, сохранения и другие доступные показатели |
| Комментарии | Количество, качество, главные темы обсуждения |
| Контекст | Подборка, внешний трафик, известность автора, продвижение |
| Гипотеза | Возможная причина результата |
| Уверенность | Высокая, средняя или низкая с объяснением |

Не сравнивать абсолютные показатели без поправки на автора, возраст публикации и доступный охват аккаунта.

## 2. Анализ аудитории

Для каждого сегмента заполнить:

| Поле | Вопрос |
|---|---|
| Кто | Должность, опыт, роль в выборе или покупке |
| Зачем приходит | Информация, решение задачи, профессиональное общение, развлечение |
| Что беспокоит | Повторяющиеся проблемы и риски |
| Что уже знает | Уровень компетенции и знакомство с темой |
| Что читает | Темы, форматы и глубина |
| Почему дочитывает | Практическая польза, новизна, фактура, позиция |
| Почему комментирует | Спор, опыт, вопрос, желание дополнить |
| Что игнорирует | Банальность, реклама, перегруз, нерелевантность |
| Какое действие нужно | Подписка, сохранение, переход, проверка, обращение |

## 3. Анализ комментариев

Отмечать тип каждого содержательного комментария:

- вопрос;
- запрос примера;
- собственный опыт;
- дополнение;
- согласие;
- несогласие;
- профессиональный спор;
- проверка или критика фактов;
- реакция только на заголовок;
- формальная реакция.

После классификации ответить:

1. Какая мысль вызвала обсуждение?
2. Комментарии относятся к сути материала или к провокационной формулировке?
3. Появились ли новые вопросы для будущих публикаций?
4. Участвовал ли автор в обсуждении?
5. Имеет ли дискуссия ценность для целевой аудитории и бизнеса?

## 4. Проверка алгоритма

Составить таблицу утверждений:

| Утверждение | Статус | Основание |
|---|---|---|
| Площадка подтверждает фактор | Факт | Официальная справка или заявление |
| Результат повторяется в выборке | Наблюдение | Несколько независимых публикаций |
| Возможна причинная связь | Гипотеза | Косвенные признаки |
| Данных недостаточно | Не установлено | Указать, чего не хватает |

Не переносить механики одной площадки на другую без проверки.

## 5. Тематическая матрица

Оценивать идеи по шкале от 1 до 5:

| Критерий | Смысл |
|---|---|
| Интерес аудитории | Насколько тема связана с текущей задачей |
| Новизна угла | Насколько подача отличается от типовых материалов |
| Доступность фактуры | Есть ли кейсы, цифры, эксперты и доказательства |
| Потенциал площадки | Насколько формат соответствует поведению аудитории |
| Бизнес-ценность | Насколько релевантны читатели продукту |
| Потенциал обсуждения | Есть ли содержательная мысль для реакции |
| Риск банальности | Насколько тема уже исчерпана конкурентами |

Для каждой темы дополнительно записать:

- вопрос аудитории;
- решение после прочтения;
- формат;
- ключевую фактуру;
- идею заголовка;
- идею визуала;
- ожидаемое действие;
- метрику проверки.

## 6. Формат итогового отчёта

Для каждого важного вывода использовать связку:

**Наблюдение:** что обнаружено.

**Доказательство:** на каких публикациях, данных или комментариях основан вывод.

**Интерпретация:** почему это могло произойти и насколько вывод надёжен.

**Решение:** что конкретно делать при подготовке контента.

Не перегружать отчёт пересказом всех изученных материалов. Выносить таблицу выборки в приложение, если она мешает основным выводам.

## 7. Редакционный чек-лист

Перед публикацией проверить:

- тема связана с реальной задачей аудитории;
- после чтения возможно конкретное решение или действие;
- заголовок точно обещает содержание;
- первый абзац сразу вводит в ситуацию;
- материал содержит новую мысль;
- ключевые выводы подтверждены фактами или примерами;
- структура соответствует выбранному формату;
- сложность языка подходит аудитории;
- коммерческая часть не разрушает доверие;
- визуал читается в ленте и поддерживает идею;
- публикация даёт основание для содержательного комментария;
- выбрана метрика, по которой будет проверена гипотеза.
