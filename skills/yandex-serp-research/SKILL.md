# Yandex SERP Research

Использует MCP-сервер `yandex-search` (пакет `yandex-search-mcp` из
https://github.com/altrr2/yandex-tools-mcp) для получения реальной выдачи
Яндекса по запросу — те же результаты, что видит человек на yandex.ru.

## Предпосылка: настройка MCP-сервера

Сервер уже прописан в `.mcp.json`. Использует **те же переменные
окружения**, что и `yandex-wordstat` (единый ключ Yandex Cloud Search API):

- `YANDEX_SEARCH_API_KEY`
- `YANDEX_FOLDER_ID` — ID **каталога** (folder), не облака (cloud) — легко
  перепутать: ID каталога виден в консоли Yandex Cloud на странице
  каталога, ID облака туда не подходит

Требования на стороне Yandex Cloud те же, что для Wordstat (роль
`search-api.webSearch.user` или `search-api.executor` на сервисном
аккаунте, scope `yc.search-api.execute` на ключе, привязанный платёжный
аккаунт). Если ключ уже настроен для Wordstat — `yandex-search` заработает
сразу, отдельно настраивать не нужно.

## Инструмент

MCP-инструмент `yandex-search` — один запрос к выдаче:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `query` | — (обязательный) | поисковый запрос |
| `maxResults` | 10 | сколько результатов вернуть (1–100) |
| `region` | автоопределение | ID региона (213 — Москва, 2 — СПб, 225 — Россия целиком) |
| `page` | 0 | пагинация |
| `includeImages` | false | включать ли картинки в результаты |
| `familyMode` | MODERATE | фильтр контента: NONE / MODERATE / STRICT |

Возвращает по каждому результату: позицию, URL, домен, заголовок,
сниппет/passages, размер, язык, кэшированную ссылку (если есть).

## Рабочий процесс

1. **Взять запрос** — обычно из `wordstat-demand-research` (топовые по
   частотности формулировки) или напрямую от пользователя.
2. **Запросить выдачу** через `yandex-search` по этому запросу (при
   необходимости — с указанием региона, если тема геозависимая).
3. **Разобрать топ-10**: какие домены присутствуют (агрегаторы, интернет-
   магазины, блоги, форумы, маркетплейсы), какой тип контента преобладает
   (обзор, инструкция, каталог, сравнение, рейтинг) — это прямой сигнал,
   какой формат Яндекс считает релевантным интенту запроса.
4. **Сравнить заголовки и сниппеты** конкурентов — что они обещают
   читателю, какие подтемы закрывают, что явно упущено (пробел = точка
   роста для новой статьи).
5. **Передать выводы дальше**: сформулированный формат/интент — во входные
   данные для структуры статьи (вместе с частотными данными из
   `wordstat-demand-research`); список LSI-кандидатов из заголовков/
   сниппетов конкурентов — как затравку для `lsi-collector`.

## Важно

- Это не «парсинг ради парсинга» — цель каждого запроса к выдаче
  сформулировать явно: какой вопрос про топ мы закрываем (формат? домены?
  пробелы в теме?).
- Не выдавай собственные домены/заголовки за содержимое выдачи — только
  то, что реально вернул `yandex-search`.
- Если нужно сравнить несколько запросов/регионов — делай отдельный вызов
  на каждую комбинацию запрос+регион, не пытайся угадывать результат по
  одному вызову.
