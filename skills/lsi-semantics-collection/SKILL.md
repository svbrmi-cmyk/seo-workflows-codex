# Сборщик LSI-слов по 21 категории

Скилл для структурированного сбора LSI-слов (Latent Semantic Indexing) под конкретную тему, товар или нишу. Слова собираются не хаотично, а по 21 чётко определённой категории, что даёт полноту семантического покрытия без "воды" и дублирования.

## Когда использовать

Триггеры: "собери LSI-слова", "семантическое ядро для...", "ключевые слова для статьи/карточки", "расширь семантику", "подбери лексику для текста про...", "LSI по теме", а также любые запросы на подготовку контента (статья, карточка товара, лендинг), где явно нужна SEO-оптимизация.

## Обязательный первый шаг: уточнить интент

**Прежде чем собирать LSI-слова, ВСЕГДА сначала спроси у пользователя:**

1. **Тема/ниша** — если пользователь её не назвал явно.
2. **Тип интента** — коммерческий или информационный. Это критично, так как влияет на приоритет категорий:
   - **Коммерческий** (карточка товара, лендинг, посадочная страница под покупку) → приоритетные категории: характеристики, критерии выбора, ценовые сегменты, бренды и модели, финансовые/юридические аспекты, социальное доказательство, сравнение/альтернативы.
   - **Информационный** (статья, гайд, обзор, "как это работает") → приоритетные категории: тематическое ядро, принцип работы, классификация, терминология, нормативы, сценарии использования, проблемы и обслуживание.

Используй `ask_user_input_v0`, чтобы задать эти вопросы одним компактным блоком (тема — если не указана, тип интента — всегда), а не идти собирать слова вслепую. Если пользователь уже явно указал и тему, и тип текста (например "карточка товара для холодильника Х") — интент можно определить самостоятельно и явно проговорить предположение вместо вопроса.

Не начинай сбор LSI без ясности по этим двум пунктам — от них зависит, какие из 21 категории раскрывать шире, а какие — по минимуму или пропустить.

## Общий процесс

Полнота (широкий охват) не получается за один проход по одному типу источников — она получается **слоями**: у каждого слоя источников свой тип лексики, и один слой физически не может дать все виды слов сразу. Пропускать слой 1.5 или 1.75 ради скорости — самая частая причина низкого охвата.

### Этап 0. Подготовка
- Зафиксировать тему и тип интента (коммерческий/информационный) — см. выше.
- Создать рабочую таблицу с 21 колонкой (по числу категорий).

### Этап 1. Концептуальный слой — редакционные источники
Собирай сырьё через `web_search`, понимая ограничения:
- **Доступно:** Википедия и отраслевые справочники, открытые статьи конкурентов в топе выдачи ("как выбрать X", "виды X", "топ брендов X"), открытые отзывы и форумы, каталоги брендов.
- **Недоступно напрямую:** Wordstat/Serpstat/Ahrefs/Keyword Planner (нужна авторизация/API), автоподсказки поисковика и виджет "люди также спрашивают" как таковые, закрытые личные кабинеты и фильтры маркетплейсов за авторизацией.
- Если для полноты нужны точные частотности или данные из Wordstat — честно скажи пользователю, что этот шаг ему нужно сделать самому, и предоставь список слов без частотных данных для дальнейшей проверки.

Этот слой закрывает: тематическое ядро, принцип работы, классификация (общая), проблемы, обслуживание, критерии выбора, сценарии использования, целевая аудитория, нормативы, экологичность. Он **не** закрывает каталожную лексику — за ней отдельный слой ниже.

Соответствие источник → категории:
| Источник | Категории |
|---|---|
| Поисковая выдача по главному запросу | тематическое ядро, классификация, бренды |
| Открытые отзывы, форумы | проблемы, эмоциональный контекст, соц. доказательство |
| Википедия / отраслевые справочники | терминология, нормативы, принцип работы |
| Каталоги брендов/производителей (редакционные обзоры) | бренды, модели, характеристики, дизайн |
| Веб-поиск по фразам "как выбрать", "виды", "топ" | критерии выбора, классификация, ценовые сегменты |

### Этап 1.5. Каталожный слой — реальные страницы конкурентов (обязательно для товарной тематики)
Для карточки/категории e-commerce редакционных статей **недостаточно в принципе** — они дают только общие рассуждения, но не то, чем реально живёт выдача. **Обязательно зафетчи (`web_fetch`) 2–3 реальные карточки/категорийные страницы топовых конкурентов** (не блог, а сам магазин) и вытащи оттуда:
- **Категория 3 (характеристики):** реальные размерные коды, если товар продаётся в типоразмерах (например 90х90, 80х80, 100х100, 120х80), а не только словесные диапазоны ("ширина 60–100 см").
- **Категория 5 (классификация):** точные названия форм из каталожных фильтров (квадратная, прямоугольная, полукруглая, четверть круга, пятиугольная, асимметричная), а не только обобщения ("угловое", "прямое").
- **Категория 16 (бренды):** бренды, которые реально встречаются в карточках/каталогах конкурентов, а не только те, что попали в топ-10 рейтинговых статей — рейтинги часто не совпадают с ассортиментом реальных магазинов.
- **Категория 2 (околотематика):** для сантехники/мебели/техники — соседние товарные категории, которые реально стоят рядом в каталоге того же магазина (например для душевых ограждений: раковины, биде, писсуары, инсталляции, полотенцесушители, мебель для ванной), даже если о них не пишут в статьях "как выбрать X".
- **Категории 9/17 (транзакционные маркеры):** "купить", "заказать", "в наличии", "под заказ", "акция", "скидка", "распродажа" — не пропускай их как "слишком общие", это законная коммерческая лексика.

### Этап 1.75. Статистическая сверка — TF-IDF/BM25 (если у пользователя есть выгрузка)
Если пользователь даёт файл текстового анализа конкурентов (экспорт из Just-Magic/Rush Analytics/Topvisor/Пиксель Тулс и т.п. со столбцами вида TF-IDF, BM25, IDF, «Пересечения (сайты)», «Медиана», «Переспам») — это третий, самостоятельный слой, не замена первых двух. Если файл есть уже на старте — можно свериться сразу после Этапа 1.5, до финального оформления по категориям; если появляется позже — прогони как контрольный проход поверх готового списка:
1. Пройди по словам файла и отметь для каждого: ✅ уже есть в собранном списке (в т.ч. как словоформа/лемма) / ➕ пропущено и относится к теме (добавь в подходящую категорию) / ❌ шаблонный шум страницы (см. стоп-лист в Этапе 3) — исключи явно и объясни почему.
2. Не добавляй слово только потому, что оно есть в выгрузке с высоким TF-IDF/BM25 — сначала проверь его отношение к теме по границам категорий (`references/categories.md`). Высокая статистическая значимость слова на странице конкурента не означает, что оно семантически относится к теме (частый случай — шаблон каталога/футер).

### Этап 2. Разбор по 21 категории
Полное описание каждой категории (определение, что не включать, вопрос-триггер, источник, примеры хорошо/плохо) — в файле `references/categories.md`. **Прочитай этот файл перед сбором слов** — в нём границы категорий, чтобы не смешивать их между собой и не выдавать абстрактные оценочные слова вместо конкретных терминов.

Кратко, 21 категория:
1. Тематическое ядро
2. Околотематика
3. Характеристики
4. Принцип работы
5. Классификация
6. Функции
7. Проблемы
8. Обслуживание
9. Критерии выбора
10. Сравнение / альтернативы
11. Сценарии использования
12. Терминология
13. Нормативы
14. Целевая аудитория
15. Ценовые сегменты
16. Бренды и модели
17. Финансовые/юридические аспекты
18. Дизайн и эстетика
19. Аксессуары и совместимость
20. Социальное доказательство
21. Экологичность

Для каждой категории:
- дай 20–30 слов/словосочетаний (1–3 слова каждое) для приоритетных по интенту категорий (см. "Обязательный первый шаг"), и не менее 15–20 для остальных — низкий охват (10–15 на категорию) недостаточен для полноценного семантического ядра
- если тема широкая и источники позволяют — не останавливайся на нижней границе диапазона, добирай слова из нескольких слоёв источников (Этапы 1, 1.5, 1.75), а не только из одного
- строго в рамках определения категории (см. references/categories.md), не смешивай с соседними
- не включай абстрактные оценочные слова ("хороший", "удобный", "качественный")
- не повторяй одно и то же слово в разных категориях

Если по какой-то категории через доступные источники не удаётся найти данных (например "нормативы" для нишевого товара без сертификации) — честно укажи это, а не выдумывай слова.

### Этап 3. Фильтрация и очистка
- Убрать дубли, привести к базовым леммам (словоформы — в отдельный подсписок, не удалять).
- Отсеять нерелевантные слова (омонимы, шум из выдачи).
- **Если сырьё включает реальные страницы сайтов (Этап 1.5/1.75) — отдельно отсеивай шаблонный шум сайта**, который не относится к теме, даже если он статистически значим на странице: элементы навигации/футера (корзина, контакты, о компании, адрес, вход в кабинет, главная, новости, сервис, фильтры каталога, "показать ещё"), юридические тексты (политика конфиденциальности, публичная оферта, обработка персональных данных, права, условия использования), пустые маркетинговые ярлыки без предметного значения (новинка/new, популярные, широкий выбор, современный, быстрый, любым способом, вид, изделия, технические — без уточнения чего). Это шум шаблона страницы, а не семантика темы — не путай с транзакционными маркерами (купить/акция/скидка), которые оставляем (см. Этап 1.5).
- Если у пользователя есть доступ к Wordstat/Keyword Planner — порекомендовать самостоятельно проверить частотность и отсечь слова с нулевым спросом.
- Ранжировать по приоритету в зависимости от интента (см. раздел "Обязательный первый шаг" выше): для коммерческого интента — усилить категории 3, 9, 15, 16, 17, 20, 10; для информационного — категории 1, 4, 5, 12, 13, 11, 7, 8.

### Этап 4. Распределение по структуре текста
Сопоставить категории с разделами будущего текста:
- Введение → околотематика, целевая аудитория
- "Что это" → тематическое ядро, терминология
- "Как работает" → принцип работы
- "Виды" → классификация
- "Характеристики" → блок характеристик
- "Как выбрать" → критерии выбора, ценовые сегменты, бренды
- "Проблемы и уход" → проблемы, обслуживание
- "Сравнение" → сравнение/альтернативы
- Заключение → социальное доказательство, эмоциональный контекст

Рекомендация по плотности: 1–2 упоминания одного термина на 300–500 слов текста, чтобы избежать переспама.

## Формат вывода

Выводи результат по категориям, сгруппированно, без лишних пояснений внутри списков:

```
## [Название категории]
слово1, слово2, слово3, ...
```

В конце — короткая сводка: какие категории были приоритетными (исходя из интента), какие источники использовались, какие категории не удалось наполнить через доступные источники (если есть).
