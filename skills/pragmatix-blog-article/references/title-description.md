# Title и Description для статьи блога

Справочные правила для этапа метаданных в `pragmatix-blog-article`. Проверять их применимость к конкретной статье и текущей документации поисковых систем.

## Что говорили поисковики на 08.11.2026; перед применением проверить актуальность

**Яндекс, title** ([справка](https://yandex.ru/support/webmaster/ru/search-results/title)):
- title даёт представление о содержании страницы и её релевантности запросу и может использоваться как заголовок сниппета; заголовок сниппета может формироваться и из контента страницы;
- не использовать общие описания вроде «Главная», «Контакты»;
- не делать слишком длинным — в выдаче может быть укорочен; длина ограничена шириной экрана;
- не перегружать ключевыми словами и не повторять их — поиск может посчитать заголовок спамом;
- избегать шаблонных title, в том числе «<Название товара> — описание, цены, характеристики, фото, отзывы»; подставлять только то, что реально есть на странице;
- бренд можно добавить в начало или конец, отделив двоеточием, дефисом или вертикальной чертой.

**Яндекс, description** ([справка](https://yandex.ru/support/webmaster/ru/indexing-options/description)):
- уникальное описание для каждой страницы, отражает содержимое, правильно выстроенные предложения;
- без злоупотребления ключевыми словами, заглавными буквами и рекламными лозунгами;
- полезная информация (цена, цвет, город доставки и т. п.), важное — в начале;
- description должен отличаться от title; не слишком короткий (не из нескольких слов), без временной и служебной информации.

**Google** ([title links](https://developers.google.com/search/docs/appearance/title-link), [snippet](https://developers.google.com/search/docs/appearance/snippet)):
- описательный и краткий title, без «Home», «Profile» и подобных; без длинного и многословного текста;
- жёсткого лимита длины нет, но в выдаче заголовок и описание обрезаются по ширине устройства;
- без переспама ключевыми словами, без повторяющегося и шаблонного текста на разных страницах;
- бренд — коротко; уникальные description для каждой страницы.

Практический ориентир длины (не требование поисковиков): Title — 45–65 знаков, главная мысль в первых 50–55; Description — 120–160 знаков, главное в первой половине.

## Отрицательная релевантность: что исключить

Отрицательная релевантность — слова и фразы в Title, которые снижают соответствие страницы главному запросу, размывают тематику или сигнализируют другой интент (по методике ГАР: artur2k.ru/tools/gar/, artur2k.ru/tools/relevantnyj-title/).

1. **Размытие семантики и переспам.** Одно, максимум два точных вхождения главного ключа. Не перечислять разнородные услуги, товары или темы («ремонт холодильников, а также стиральных машин, микроволновок…»).
2. **Несоответствие интенту.** Коммерческая страница — без информационных маркеров («как выбрать», «своими руками», «история»). Статья — без коммерческих маркеров («купить», «цена», «заказать»), если страница не продаёт. Не обещать разделов, которых нет в тексте (например, «стратегии», «примеры», «цены», «отзывы» без соответствующего блока).
3. **Мусорные и шаблонные слова.** «Главная страница», «Добро пожаловать», «Каталог», «Официальный сайт» без смысла, цепочки «описание, цены, характеристики, фото, отзывы», лишние предлоги и восклицания.
4. **Географическое несоответствие.** Регион только если страница и услуга к нему действительно относятся.
5. **Повторы.** Одно и то же слово не повторять в Title; Description не дублирует Title.

Влияние этих ошибок на позиции или показанный заголовок оценивают по данным конкретного проекта; фиксированного последствия нет.

## Порядок работы

1. **Входные данные:** главный ключ и 1–3 дополнительных (из ТЗ или wordstat-demand-research), тип страницы и интент, H1, структура и фактическое содержание текста, рекомендации ГАР (если есть отчёт), бренд, регион (если релевантен).
2. **Title:**
   - главный ключ — один раз, ближе к началу;
   - маркер интента: для статьи «что это», «как», «простыми словами», «гайд»; для коммерции — действие или предмет продажи, регион, ключевое УТП из текста;
   - 1–2 сильных тематических слова из ГАР (у ≥50% конкурентов), если они отражают реальное содержание;
   - каждое обещание Title подтверждается разделом или блоком страницы;
   - грамматически цельная, читаемая фраза, привлекательная для клика; бренд — только в конце или начале через разделитель, если нужен;
   - Title и H1 должны различаться: не только не совпадать дословно, но и не быть перестановкой одних и тех же слов (больше 60% общих слов — переформулировать). Тема та же, но Title даёт другой угол или дополнительный ключ из ТЗ (например, H1 «Поиск с ИИ: как работают Яндекс Нейро, Google AI и ChatGPT Search» → Title «Поиск с ИИ: чем нейросеть-поисковик отличается от обычной выдачи»).
3. **Description:**
   - 1–2 законченных предложения: что пользователь узнает или получит на странице;
   - главный ключ или его вариант — один раз, естественно; дополнительные ключи и LSI — без перечня;
   - для коммерции — конкретика из страницы (цена от, сроки, доставка, гарантия), только если она есть в тексте и подтверждена;
   - без капслока, восклицаний, лозунгов, служебной информации; отличается от Title.
4. **Проверка скриптом** `../scripts/check_meta.py` (длина, вхождения ключа, повторы, мусорные и интентные маркеры, совпадение Title и Description).
5. **Ручная проверка по чек-листу** ниже.
6. **Выдача:** Title и Description с длиной в знаках и 1–2 строками обоснования: какие слова дают релевантность, что убрано и почему. Если Title из ТЗ содержит отрицательную релевантность — предложить замену и объяснить причину.

## Чек-лист перед сдачей

- [ ] Главный ключ в Title 1–2 раза, ближе к началу.
- [ ] Маркер интента соответствует типу страницы.
- [ ] Каждое обещание Title есть в тексте страницы.
- [ ] Нет разнородных перечислений, мусорных слов, шаблонных хвостов, лишней географии.
- [ ] Нет повторов слов в Title; Description не дублирует Title.
- [ ] Есть 1–2 сильных слова из ГАР, если отчёт есть.
- [ ] Title и Description читаются как нормальные фразы; Description — 1–2 законченных предложения.
- [ ] Длина в ориентирах: Title ≈ 45–65, Description ≈ 120–160 знаков; главное — в начале.
- [ ] Все факты в Description (цены, сроки, гарантии) подтверждены текстом страницы или данными заказчика.

## Примеры

Статья, ключ «аутрич»:
- Плохо: «Аутрич в SEO: что это, как работает, стратегии» — в тексте нет раздела о стратегиях, «как работает» не несёт тематики.
- Хорошо: «Аутрич в SEO: что это, как писать письма и получать ссылки» (58) — ключ один раз, информационный интент, LSI «письма», «ссылки» из ГАР, каждая часть есть в тексте.

Коммерческая страница, ключ «ремонт холодильников»:
- Плохо: «Ремонт холодильников, стиральных машин, микроволновок — недорого! Главная».
- Хорошо: «Ремонт холодильников на дому в Казани — выезд мастера в день заявки» — если страница о Казани и выезд в день заявки указан в условиях.
