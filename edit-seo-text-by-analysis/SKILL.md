# Насыщение текста LSI по медиане

Редактировать уже готовый текст. Цель — расширить тематический словарь и глубину
раскрытия темы, а не механически увеличить число повторов.

Главный принцип:

`медиана определяет приоритет и верхний предел → релевантность определяет, можно ли
использовать слово → смысл и читабельность определяют конкретную формулировку`.

Ни одно добавление не должно менять содержание, факты, выводы, характеристики,
сравнения или коммерческий смысл исходника.

## Входные данные

Обязательно получить:

1. исходный текст;
2. одну или несколько Excel-таблиц LSI-анализа.

Опционально учитывать:

- отдельный файл нерелевантных точных словоформ;
- дополнительный список слов ширины;
- таблицу глубины со столбцами `Повторы`, `Максимум по рекомендациям` и
  `Добавить/Удалить`;
- повторную таблицу анализатора после предыдущей итерации.

Не требовать отдельный список ширины: основным словарём насыщения служат релевантные
строки Excel-таблицы.

## 1. Прочитать Excel

Если обычный читатель XLSX недоступен, запустить:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/extract-xlsx-analysis.ps1 -Path analysis.xlsx
```

На каждом листе найти строку заголовков и сопоставить столбцы по названию, а не по
букве:

- `Слово` — название группы;
- `Словоформа` или `Словоформы` — точные формы, входящие в группу;
- `Медиана` — целевой ориентир и жёсткий верхний предел;
- `Текст у вас`, `Ваша страница` или эквивалентный столбец — справочный текущий
  показатель анализатора.

Допустимы различия регистра, пробелов, переносов и уточнений в скобках. Не подменять
`Медиану` минимумом, максимумом, TF-IDF, BM25 или частотой отдельного конкурента.

Разбирать словоформы по реальному разделителю ячейки: запятая, точка с запятой или
перенос строки. Не дробить многословные фразы на отдельные слова.

Для каждой строки получить:

`группа → словоформы → медиана → показатель анализатора`.

Строки без числовой медианы не использовать как цель. Если обязательные столбцы не
найдены, назвать лист и найденные заголовки, не угадывая структуру.

## 2. Выделить вспомогательные слова на удаление

Если дана таблица глубины, найти столбцы:

- `Слово`;
- `Словоформы`;
- `Повторы`;
- `Максимум по рекомендациям`;
- `Добавить/Удалить`.

Строку считать рекомендацией на сокращение только тогда, когда общий столбец
`Добавить/Удалить` содержит отрицательное число.

Не использовать отрицательное значение `Текст Добавить/Удалить` как самостоятельный
признак удаления: оно может означать перераспределение слова между текстом, ссылками и
другими зонами страницы. Иначе в список удаления ошибочно попадёт релевантное
высокомедианное ядро.

Рассчитать:

`сколько удалить = abs(Добавить/Удалить)`

`сколько оставить = Повторы + Добавить/Удалить`

Сверить `сколько оставить` с `Максимум по рекомендациям`. При корректной таблице
значения должны совпасть. Если они различаются, зафиксировать конфликт и не выбирать
цель молча.

Сокращать суммарное количество всех форм из ячейки `Словоформы`, а не только форму из
столбца `Слово`.

Правила сокращения:

- убрать ровно рекомендованное число употреблений, если это возможно без потери
  содержания;
- сначала заменить повторы синонимами, местоимениями, гиперонимами или более точными
  контекстными обозначениями;
- для названий серий, брендов и технических терминов оставить разрешённый минимум в
  ключевом месте;
- не удалять уникальный факт вместе со словом;
- после правки пересчитать всю группу и не опускаться ниже рассчитанной цели без
  необходимости.

Пример: `Повторы = 4`, `Добавить/Удалить = −3`, `Максимум = 1` означает оставить одно
употребление группы.

## 3. Удалить шум до ранжирования

Сначала классифицировать каждую строку:

- **релевантна** — описывает тему, объект, свойства, выбор, применение или условия,
  которые уже раскрыты в тексте;
- **условно релевантна** — может быть использована только без добавления нового факта;
- **служебная** — относится к футеру, меню, регистрации, аккаунту или интерфейсу;
- **юридический шум** — `конфиденциальность`, `обработка персональных данных`,
  `публичная оферта`, `пароль`, `вход`, `согласие на обработку` и аналогичные элементы
  чужих страниц;
- **чужая тема** — бренд, категория, услуга или свойство, отсутствующее в исходнике.

Служебные, юридические и чужие строки исключить независимо от высокой медианы. Не
вставлять их и не учитывать при оценке покрытия.

Если пользователь дал файл нерелевантных слов, его точные формы также исключить.
Совпадение проверять на границах слов, без стемминга. Если такая форма уже есть в
исходнике и не нужна по смыслу, убрать или заменить её.

## 4. Посчитать фактические вхождения

Для каждой релевантной группы самостоятельно посчитать в исходном тексте сумму её
словоформ:

- без учёта регистра;
- нормализуя `ё` и `е` так же, как это делает анализатор;
- на границах слов;
- с учётом заголовков, списков и подписей, входящих в текст;
- не считая часть другого слова совпадением;
- не смешивая разные группы.

Показатель `Текст у вас` использовать для сверки, но не вместо собственного подсчёта.
При расхождении работать по фактическому тексту и отметить разницу.

Вычислить:

`доступно добавить = max(0, медиана − фактическое количество)`.

Жёсткое правило: после редактирования группа не должна превышать медиану. Если исходный
текст уже выше медианы, не добавлять её и по возможности сократить лишние повторы
естественными заменами.

## 5. Ранжировать LSI по медиане

Отсортировать релевантные группы по медиане по убыванию. Не редактировать текст до
готовности ранжированного плана.

Разделить словарь:

### Ядро

Топ-слова с наибольшими медианами: обычно первые 10–15 релевантных групп или группы до
явного падения значений. Это обязательный смысловой костяк.

- тянуть к медиане агрессивнее остальных;
- стремиться закрыть большую часть доступного разрыва;
- использовать разные разрешённые словоформы;
- распределять по нескольким разделам.

### Средний приоритет

Релевантные слова ниже ядра с заметной медианой.

- добавлять после ядра;
- приближать к медиане там, где термин логично уточняет содержание;
- не вытеснять ими слова ядра.

### Низкий приоритет

Слова с небольшой медианой, обычно 1–5 относительно конкретной таблицы.

- добавлять не более 1–2 новых употреблений;
- никогда не превышать медиану;
- пропускать, если вставка не даёт тематической глубины.

Границы определять по распределению конкретной таблицы, а не по одному неизменному
числу. При одинаковой медиане выше ставить слово, которое раскрывает отдельный аспект
темы, а не дублирует уже частую лексику.

## 6. Освободить текст от узкой семантики

До добавления новых слов найти лексику, которая занимает слишком большую долю текста:

- общие тематические слова с низкой медианой;
- повторяющиеся слова, отсутствующие в таблице;
- одинаковые названия объекта в соседних предложениях;
- тавтологические прилагательные и коммерческие клише.

Сократить лишние повторы с помощью:

- точных синонимов;
- местоимений;
- гиперонимов;
- контекстных обозначений;
- перестройки предложения.

Не удалять базовое название темы полностью. Сохранить его в заголовках и ключевых
местах, но не позволять ему забивать текст только потому, что это естественное слово
темы.

Не заменять термин синонимом, если изменится техническое значение, субъект факта или
область утверждения.

### Не переносить переспам на один синоним

Запрещена массовая замена всех лишних употреблений одним и тем же словом. Такая
подстановка не расширяет семантику, а только создаёт новый переспам.

Для каждого сокращаемого слова заранее составить контекстный набор замен:

- пропуск слова, если смысл остаётся ясным;
- местоимение;
- точный синоним;
- гипероним или название категории;
- конкретное название детали, функции, серии или объекта;
- перестройка предложения без прямого заменителя.

Распределять варианты по контексту и не использовать один вариант во всех местах.
Если новое слово есть в LSI-таблице, соблюдать его медиану или отрицательную
рекомендацию. Если его нет в таблице, по умолчанию вводить не более 1–2 раз и не
повторять в соседних абзацах.

После каждой серии замен пересчитать не только исходную группу, но и все слова,
которые использовались вместо неё. Если один заменитель начинает доминировать,
разнообразить формулировки повторно. Проверять таким образом и ранее внесённые
подстановки: `встроенная`, `пара`, `отдельно`, `наборы`, `предметы`, `решения`,
названия серий и другие слова из очередной таблицы анализа не считать естественными
исключениями.

## 7. Насыщать текст по проходам

Редактировать в таком порядке:

1. выполнить отрицательные рекомендации `Добавить/Удалить`;
2. удалить служебный и юридический шум;
3. сократить повторы остальной неприоритетной лексики;
4. распределить слова ядра по всем подходящим разделам;
5. добавить средний приоритет;
6. точечно добавить низкий приоритет;
7. использовать релевантные слова дополнительного списка ширины, если он дан, не
   нарушая медианные лимиты групп;
8. пересчитать слова-заменители и устранить перенесённый на них переспам;
9. вычитать весь текст стилистически и технически.

Перед вставкой определить, какой существующий факт или мысль можно выразить этой
лексикой. Не создавать новый факт ради слова.

Распределять употребления:

- не несколько одинаковых форм в одном предложении;
- не в соседних предложениях без необходимости;
- не весь дефицит в одном абзаце;
- термин материалов — в разделе материалов;
- термин конструкции — в описании устройства;
- термин выбора — в рекомендациях по выбору;
- коммерческий термин — только в блоке подтверждённых условий покупки.

Высокая медиана означает больше естественных употреблений по всему тексту, а не
скопление повторов.

После каждого прохода пересчитывать затронутые группы. Если следующая вставка превысит
медиану, не делать её.

## 8. Сохранить текст

При любой правке:

- сохранять все исходные факты, ограничения и выводы;
- не добавлять свойства, сертификаты, размеры, цены, гарантии, бренды и сравнения;
- не сокращать полезное содержание;
- сохранять структуру и назначение текста;
- соблюдать грамматику, управление, терминологию и стиль;
- вписывать слово только в правильном значении;
- предпочитать недобор искусственной формулировке.

Полностью переписывать абзац только тогда, когда локальная правка невозможна. После
переписывания сверять смысл с исходником предложение за предложением.

## 9. Финальная проверка

Повторно посчитать все релевантные группы и проверить:

- `стало <= медиана` для каждой группы;
- каждая отрицательная рекомендация `Добавить/Удалить` выполнена до рассчитанного
  остатка либо имеет объяснение;
- ядро получило больший вес, чем низкоприоритетная лексика;
- высокомедианные слова приблизились к цели настолько, насколько позволяет текст;
- низкоприоритетные слова добавлены не более 1–2 раз;
- служебные и нерелевантные слова не добавлены;
- повторы отсутствующей в таблице лексики сокращены;
- массовая замена не перенесла переспам на один новый синоним;
- термины распределены по всему тексту;
- нет новых, исчезнувших или изменённых фактов;
- формулировки естественны, логичны, стилистически и технически корректны.

Перечитать результат без таблицы. Любую фразу, похожую на вставку ради счётчика,
переписать или удалить, даже если возникнет обоснованный недобор.

## Результат

Сохранить новый UTF-8 файл, не перезаписывая исходник. По умолчанию использовать
`D:\CODEX\outputs`.

Выдать:

1. полный отредактированный текст;
2. путь к файлу;
3. компактную проверку:
   - группа;
   - приоритет;
   - медиана;
   - было;
   - стало;
   - статус или причина недобора;
4. список исключённого служебного и нерелевантного шума.

Не заявлять о росте семантической ширины без фактического пересчёта.
