# Редактирование SEO-текста по LSI-анализу

Редактировать готовый текст, а не создавать новый. Расширять тематический словарь за
счёт более точного выражения уже имеющихся мыслей.

Приоритеты:

`факты и точность → релевантность → ограничения таблиц → естественность → полнота
заполнения медианы`.

Недобор допустим. Новые факты, искусственные фразы и перенос переспама недопустимы.
После формирования ядра увеличивать ширину прежде всего числом разных релевантных
групп, а не дополнительными повторами уже покрытых слов.

## Входные данные

Обязательно получить:

1. исходный текст;
2. LSI-таблицу слов с медианами.

Дополнительно принимать:

- таблицу глубины с `Добавить/Удалить`;
- таблицу N-грамм;
- файл нерелевантных слов и целевых остатков;
- список слов ширины;
- повторный анализ после предыдущей редакции.

Сохранять результат новым UTF-8-файлом в `D:\CODEX\outputs`, не перезаписывая
исходник.

## 1. Назначить роли таблицам

Не смешивать числовые цели разных источников:

1. **LSI-слова** — основной словарь, приоритет и верхний предел группы по `Медиане`.
2. **Глубина** — группы на сокращение по отрицательному общему
   `Добавить/Удалить`.
3. **N-граммы** — вторичный ориентир для естественных сочетаний. Их медиана не
   отменяет лимиты входящих слов.
4. **Нерелевантные слова** — запрет на добавление и, если указано число, целевой
   остаток.
5. **Слова ширины** — дополнительные кандидаты, а не разрешение на безлимитные
   повторы.

Если даны две таблицы одного типа из разных итераций, не складывать значения.
Использовать явно названную пользователем актуальную таблицу; иначе зафиксировать
конфликт.

Поддерживаемые схемы и варианты заголовков описаны в
[references/analyzer-tables.md](references/analyzer-tables.md). Читать этот файл при
разборе Excel.

## 2. Построить группы словоформ

Сопоставлять заголовки по нормализованному названию, а не по букве столбца.

Для LSI-таблиц типа `Сводим формы слов`:

1. взять группу, медиану и идентификатор `Связь слов с другим листом`;
2. на листе `Все формы слов` собрать строки с тем же идентификатором;
3. добавить главное слово группы;
4. дополнить формами одноимённой группы из таблицы глубины;
5. удалить дубли.

Разделять перечисленные формы по запятой, точке с запятой или переносу строки.
Многословную N-грамму не дробить.

Строки без числовой медианы не использовать как цель. Пустые листы пропускать.
При неизвестной схеме вывести найденные заголовки и не угадывать столбцы.

## 3. Посчитать исходное состояние

Запустить:

```powershell
python scripts/validate-lsi-text.py --source source.txt --text source.txt `
  --lsi lsi.xlsx --depth depth.xlsx --phrases phrases.xlsx
```

Неуказанные дополнительные таблицы опускать.

Основной точный подсчёт выполнять:

- без учёта регистра;
- с нормализацией `ё`/`е`;
- на границах слов;
- по сумме уникальных форм группы;
- во всём предоставленном тексте, включая заголовки и списки;
- без двойного подсчёта одинаковой формы внутри одной группы.

Показатель анализатора `Текст у вас`, `Ваша страница` или `На нашем сайте`
использовать для сверки. Если он отличается от собственного подсчёта, работать по
фактическому файлу и указать расхождение.

### Морфологическая страховка

Таблица может не перечислить все формы: например, содержать `встроенный`, но
пропустить `встроенным`.

После точного подсчёта отдельно просмотреть текст на другие очевидные формы той же
леммы. Не считать совпадением слово только из-за общего короткого корня. Подтверждать
форму по грамматике и значению. Такие кандидаты включать в ручной аудит и итоговый
пересчёт группы.

## 4. Классифицировать лексику до редактирования

Для каждой группы определить:

- **релевантная** — раскрывает существующую мысль или свойство;
- **условно релевантная** — допустима без добавления нового факта;
- **служебная** — корзина, вход, пароль, навигация, интерфейс;
- **юридический шум** — персональные данные, оферта, авторские права и подобное;
- **чужая тема** — бренд, категория, серия или свойство, добавление которых создаст
  отсутствующий факт;
- **неизменяемая сущность** — бренд, серия, артикул, размер, цена, материал,
  технический термин или иное точное значение.

Служебный, юридический и чужой шум не вставлять независимо от медианы.

Слово, отсутствующее в исходнике, не считать чужой темой автоматически. Если оно
точнее выражает уже имеющийся факт, это кандидат для семантической ширины.

Неизменяемую сущность не заменять синонимом. Можно сократить только её повторные
упоминания, оставив название в месте, где оно необходимо для сохранения факта.

## 5. Рассчитать цели и разрешить конфликты

### LSI-группы

Рассчитать:

`можно добавить = max(0, медиана − фактическое количество)`.

Для новых вставок медиана — жёсткий предел. Если исходник уже выше медианы, ничего не
добавлять и сокращать только устранимые повторы.

Если дальнейшее сокращение уничтожит уникальный факт или точное название, оставить
минимально необходимое превышение и отметить его как `fact-preservation exception`.
Не заявлять, что лимит выполнен.

### Отрицательные рекомендации глубины

Маркер сокращения:

`общий Добавить/Удалить < 0`.

Рассчитать:

`квота удаления = abs(Добавить/Удалить)`

`общий целевой остаток = Повторы + Добавить/Удалить`

Сверить остаток с `Максимум по рекомендациям`.

`Текст Добавить/Удалить` не использовать как самостоятельный маркер: он отражает
распределение между текстом, ссылками и другими зонами. По умолчанию редактировать
предоставленный текст по общей квоте.

Если фактический текст не совпадает с `Повторы`, считать таблицу несинхронной:

`предварительный остаток текста = max(0, фактическое количество − квота удаления)`.

Не выдавать его за подтверждённый анализатором максимум. Рекомендовать повторный
анализ.

### Конфликт источников

Применять порядок:

1. сохранить факт и точное значение;
2. выполнить отрицательную рекомендацию, если это не уничтожает факт;
3. не превысить медиану LSI новыми вставками;
4. использовать N-грамму только в пределах лимитов всех её компонентов;
5. предпочесть недобор искусственной формулировке.

Пример: медиана `тумба = 2`, а медиана фразы `тумба под раковину = 21`. Фразу можно
использовать не более двух раз, потому что лимит слова `тумба` имеет приоритет.

## 6. Ранжировать словарь

Сначала исключить шум, затем сортировать релевантные LSI-группы по медиане.

### Ядро

Выделить первые 10–15 релевантных групп или группы до явного падения медиан:

- стремиться закрыть большую часть естественно доступного разрыва;
- использовать разные разрешённые формы;
- распределять по нескольким смысловым разделам.

Высокая медиана не обязывает заполнять дефицит, если слово относится к интерфейсу,
покупке или ограниченному коммерческому блоку. Например, `наличие` допустимо только в
условиях покупки и карточках товара.

### Средний и низкий приоритет

- средний приоритет добавлять после ядра;
- до второго нового повтора уже покрытой средней или низкой группы пройти все
  непокрытые релевантные группы;
- релевантную группу с медианой 1 закрывать одним естественным употреблением, если
  оно выражает существующий факт;
- низкую медиану выше 1 обычно закрывать одним новым употреблением, максимум двумя;
- пропускать слово, которое не добавляет тематической глубины.

Считать два показателя:

`ширина = покрытые релевантные группы / все релевантные группы с медианой > 0`

`глубина = сумма min(факт, медиана) / сумма медиан релевантных групп`

Автоматический отчёт валидатора показывает `raw_width` и `raw_depth` по всем группам
с положительной медианой. Это только диагностические показатели: служебный,
юридический и фактологически неподтверждённый шум ещё входит в знаменатель. После
ручной классификации обязательно пересчитать итоговые показатели только по
релевантным группам. Не поднимать сырую ширину вставкой шума.

Не улучшать глубину ценой остановки прохода по ширине. После разумного заполнения ядра
сначала увеличивать число покрытых групп.

## 7. Сократить узкую семантику

Сначала найти:

- отрицательные группы глубины;
- исходные превышения медианы;
- повторяющиеся слова вне таблицы;
- одинаковые названия объекта в соседних предложениях;
- прежние массовые подстановки.

Не заменять все употребления одним синонимом. Это правило распространяется на всю
лексику, добавленную при редактуре, а не только на замены сокращаемых слов.

Отдельно контролировать:

- глаголы: `уточнить`, `проверить`, `выбрать`, `предусмотреть`;
- наречия: `заранее`, `отдельно`, `самостоятельно`;
- прилагательные: `актуальный`, `подходящий`, `удобный`;
- модальные связки: `следует`, `можно`, `необходимо`, `важно`;
- одинаковые начала и окончания предложений;
- повторяющийся каркас вокруг одного LSI-слова.

Нельзя добавлять несколько употреблений `наличие` через один шаблон
`актуальное наличие уточняйте заранее`. Само целевое слово может повторяться в
пределах медианы, но его глагольная, наречная и оценочная обвязка должна меняться по
смыслу: наличие указывается в карточке, доступность проверяют перед заказом, сведения
сверяют у продавца.

Для каждой сокращаемой группы использовать контекстный набор:

- удалить необязательное слово;
- перестроить предложение без прямого заменителя;
- применить местоимение;
- назвать конкретную деталь, функцию или категорию;
- использовать точный синоним или гипероним.

Названия брендов и серий не входят в набор синонимов. После первого полного
упоминания допустимы `эта серия`, `модель SC3005`, `первые две линейки`, если субъект
остаётся однозначным.

Считать не только итоговую частоту заменителя, но и сколько раз каждое слово или
шаблон **добавлен**. Новое слово вне таблицы по умолчанию вводить один раз, максимум
два раза в разных контекстах. Если оно уже было в исходнике, не увеличивать его
доминирование.

После серии правок пересчитать целевые группы, семейства заменителей, добавленные
глаголы, наречия, прилагательные и повторяющиеся двух- и трёхсловные каркасы. При
новом переспаме повторно разнообразить формулировки.

Если повторный анализ вынес добавленную обвязку в отрицательные рекомендации
глубины — например, `заранее`, `выберите`, `актуальный` или искусственно размноженный
технический термин, — считать это доказанным переносом переспама. Сократить весь
каркас, а не заменять отмеченное слово одним новым массовым аналогом.

## 8. Добавить ширину и глубину

Работать проходами:

1. сохранить карту фактов и неизменяемых сущностей;
2. сократить отрицательные группы и исходные превышения;
3. распределить ядро;
4. добавить средний приоритет;
5. выполнить отдельный проход ширины: по одному разу закрыть максимум разных
   релевантных групп;
6. только затем добавить вторые употребления низкого приоритета;
7. обработать список ширины;
8. проверить N-граммы;
9. пересчитать заменители и языковую обвязку;
10. вычитать текст без таблиц.

Для слова ширины:

- если оно входит в LSI-группу, использовать свободный остаток до медианы;
- если его нет в LSI, вставить один раз в наиболее точный контекст;
- второе употребление разрешить только для другого смыслового аспекта;
- нерелевантное или требующее нового факта слово пропустить.

«Вставить по максимуму» означает покрыть максимум подходящих **разных** слов, а не
повторить одно слово максимально много раз.

Распределять лексику по смыслу: материалы — в материалы, конструкцию — в устройство,
выбор — в рекомендации, коммерческие слова — в условия покупки. Не закрывать дефицит
в одном абзаце.

## 9. Финальная проверка

Обязательно повторно запустить `validate-lsi-text.py`, передав исходник и итоговый
текст.

Проверить:

- новые вхождения не превысили медианы;
- каждое исходное превышение сокращено либо имеет исключение сохранения факта;
- каждая актуальная отрицательная группа достигла цели либо объяснена;
- ядро получило больший вес, чем низкоприоритетная лексика;
- служебный и нерелевантный шум не добавлен;
- ни существительная замена, ни глагольная, наречная, оценочная или модальная
  обвязка не стали новым переспамом;
- ширина посчитана по релевантным группам, а не оценена на глаз;
- названия, артикулы, числа, свойства, ограничения и выводы сохранены;
- текст естественен, логичен, грамматически и технически корректен.

Перечитать текст без таблицы. Фразу, заметно написанную ради счётчика, удалить или
переписать, даже если возникнет недобор.

## Результат

Выдать:

1. полный отредактированный текст и путь к файлу;
2. таблицу `группа → приоритет → медиана/цель → было → стало → статус`;
3. обоснованные недоборы и исключения сохранения фактов;
4. список исключённого шума;
5. ширину и глубину до/после по отфильтрованным релевантным группам;
6. добавленные слова и языковые каркасы, потребовавшие анти-монокультурной правки;
7. найденные конфликты таблиц и рекомендацию повторного анализа при несинхронности.

Не заявлять о росте семантической ширины без фактического пересчёта.
